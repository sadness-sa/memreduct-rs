环境：Linux x86_64；Rust stable 1.99.1；GNU MinGW GCC 13-posix；Windows 目标 `x86_64-pc-windows-gnu`。依赖为随源码提供的 `Cargo.lock` 版本。

| 检查 | 结果 |
| --- | --- |
| `cargo fmt --check` | 通过 |
| `cargo clippy --all-targets --locked -- -D warnings` | 通过（Linux） |
| Windows GNU 目标全目标 Clippy，warnings 视为错误 | 通过 |
| `cargo test --locked` | 7 个测试通过（Linux；不调用 Windows 清理接口） |
| Windows GNU Release 构建 | GUI 和 CLI 两个 x64 EXE 生成成功 |
| PE 检查 | GUI 为 Windows GUI 子系统；CLI 为 Console 子系统；清单资源已嵌入 |

测试覆盖：持续高压、短暂峰值、回差、冷却、定时、忙碌、禁用、手动清理后延迟、采样中断、重载保留冷却、错误配置不覆盖、参数错误、部分清理失败、负的内存差值。

GUI/CLI 的体积约为 610 KiB / 519 KiB，具体字节数与 SHA-256 在交付包 `SHA256SUMS.txt` 中。这些体积是本次 GNU 构建的结果，其他编译器和工具链可能不同。

## Windows 验收清单

建议按以下顺序在 Windows 10 和 Windows 11 各执行一次，记录 OS 构建号和程序版本。

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 普通权限监控 | 双击 GUI，运行 CLI `status --json` | 可用内存不大于总内存，计数变化与任务管理器口径基本一致；提交量不是“页面文件用量” |
| 普通权限清理 | 运行保守清理 | 如缺权限显示具体错误，不表示成功；CLI 返回非零 |
| 管理员保守清理 | 提升后运行 conservative | 成功或返回明确 NTSTATUS；全部结果有记录，不能仅凭数字大小判断成功 |
| 均衡/强力 | 逐个执行；强力分别取消和确认 | 取消不执行；确认后逐项报告；UI 可持续响应 |
| CLI 确认 | aggressive 不加 `--yes` | 拒绝执行；加参数后仍受系统权限限制 |
| 关闭/恢复 | 关闭窗口，托盘左键恢复 | 进程仍在，主窗口可恢复 |
| 托盘异常 | 重启 Explorer | 托盘重建；失败时恢复可见主窗口 |
| 快捷键冲突 | 另一程序占用 Ctrl+Alt+M | 显示被占用；按钮和菜单仍可用 |
| 单实例 | 连续启动 GUI 两次 | 原实例恢复，不启动第二个常驻实例 |
| UAC | 点击管理员重启；分别同意和取消 | 同意后旧实例退出、新实例接管；取消保留旧实例 |
| 跨进程串行 | GUI 清理时立即运行 CLI 清理 | 同一会话第二个请求返回“正在清理” |
| 配置错误 | 非法阈值或 TOML，再重载 | 报告错误，现有运行配置继续使用，错误文件原样保留 |
| 配置写保护 | 便携目录设为不可写，操作配置开关 | 显示保存失败，控件回滚到原值 |
| 自动清理 | 设置阈值 50、持续 3 秒、冷却 60 秒，在测试负载下观察 | 仅持续过阈值后触发，未回落时不因高压重复；仅保守模式 |
| 定时清理 | interval_seconds=60，auto_enabled=true | 受冷却和忙碌约束；不会每秒提交 |
| 采样/清理出错 | 保持普通权限或使用不支持的测试系统 | 不无限重试；后置采样失败仍保留已完成操作结果 |
| 显示缩放 | 100%、150%、200% 启动 GUI | 文字不遮挡、控件可访问；跨屏 DPI 重排是当前限制 |
| 退出 | 清理中退出，再等待完成后退出 | 忙碌时提示等待；完成后无托盘残留 |

## 性能对照方法

在同一机器、同一系统构建和同一负载下比较原版与 Rust 版，避免用单次“可用内存增加”作为性能结论。

1. 空闲常驻 10 分钟，分别记录 Private Bytes、Working Set、CPU 时间增量和句柄数；GUI 可见、隐藏到托盘各测一次。
2. 使用同一可复现负载，分别测试不清理、保守、均衡、强力；清理前 30 秒到清理后 120 秒记录系统可用内存、提交量、硬缺页和磁盘读写。
3. 游戏负载记录帧时间分位数和卡顿次数，至少重复 5 轮，交替测试顺序，报告中位数和变化范围。
4. 若仅可用内存上升，而硬缺页、帧时间或磁盘读取变差，应记录为收益不足或退化，不推广强力清理。

不得根据本次编译结果推算实际 CPU 或内存占用；待实机数据返回后再决定是否调整默认策略或加入进程排除功能。
